# 纯复盘系统 · 数据更新编排（v2）

## 核心规则

```
交易日 09:30~15:00  →  展示上一个交易日数据 + 黄色标签"昨日数据"
交易日 15:00 之后   →  全量更新为当日数据
非交易日            →  展示最近交易日数据
```

## 每日更新流程

### ① 开盘前（09:00~09:25）：无操作

系统展示上一个交易日数据。前端显示黄色标签 `⏳ 未开盘 · 展示上一个交易日数据`。

### ② 交易时段（09:30~15:00）：仅资讯更新

| 数据 | 操作 | 说明 |
|:-----|:-----|:------|
| 全球资讯/财联社 | 每 5min 刷新 Redis | 唯一在交易时段更新的数据 |
| 北向资金分时（262点） | 盘中实时采集 | 只有北向在交易时段有分钟级数据 |
| **其余全部数据** | **不更新** | 展示昨日收盘快照 |

> 此时各页面顶部显示提示标签：**"⏳ 交易时段 · 展示昨日数据"**

### ③ 收盘后（15:00~15:30）：全量更新（每天一次）

收盘后触发 `data_rollover()`，按以下顺序执行：

```
┌─────────────────────────────────────────────────┐
│            data_rollover()                        │
│            (收盘后仅执行一次)                       │
├─────────────────────────────────────────────────┤
│                                                   │
│  Step 1: 冻结今日收盘行情（从腾讯API采集）           │
│  ├── stock_basic（全量5542只，含PE/PB/市值）        │
│  ├── index_list（5大指数收盘价）                    │
│  ├── stats（涨跌平统计）                            │
│  └── top_gainers/losers/high_volume（涨跌排行）     │
│                                                   │
│  Step 2: 信号数据采集（东财/同花顺API）              │
│  ├── northbound（北向资金日终汇总）                  │
│  ├── hot_reason（题材热点）                         │
│  ├── dragon_tiger（龙虎榜）                         │
│  ├── industry_compare（行业对比）                    │
│  ├── industry_treemap（行业云图+成分股）             │
│  ├── fund_flow（40只热门股资金流向）                  │
│  └── lockup_upcoming（限售解禁）                     │
│                                                   │
│  Step 3: K线刷新（后台Popen）                       │
│  ├── 日K（365天，全量）                             │
│  ├── 分钟K（5/15/30/60min，前500只）               │
│  └── 指数K线（5指数）                               │
│                                                   │
│  Step 4: MySQL 归档（每日1次）                      │
│  ├── stock_daily（+今日收盘价，不覆盖历史）           │
│  ├── index_daily                                   │
│  ├── northbound_daily                              │
│  ├── hot_reason_daily                              │
│  ├── dragon_tiger_daily                            │
│  ├── industry_daily                                │
│  └── info_news（当日新闻归档）                       │
│                                                   │
└─────────────────────────────────────────────────┘
```

### ④ 收盘后验证（15:30~15:35）：数据一致性检查

```
check_rollover()
├── stock_basic 条数 > 5000                 → ✅
├── index_list = 5 条                       → ✅
├── northbound 日期 = 今天                  → ✅
├── hot_reason 条数 > 50                   → ✅  
├── dragon_tiger 条数 > 100                → ✅
├── industry_compare 条数 > 90             → ✅
├── K线最新日期 = 今天                       → ✅
└── MySQL 7张表归档完成                      → ✅
  → 若有失败，自动重试 Step 对应的子步骤
```

## run_collector.py 循环简化

```
main_loop（每 5min 循环）:
  │
  ├── 交易日 09:00~15:00:
  │   ├── 仅刷新 新闻（Redis）         ← 盘中唯一更新
  │   └── 北向资金分时采集              ← 盘中唯一补充
  │
  ├── 交易日 15:00~15:30:
  │   └── 调用 data_rollover()          ← 全量更新
  │        └── 完成后续验证
  │
  └── 非交易日:
      └── 不做任何操作
```

## 核心原则

1. **一次写入，全天展示** — 数据每天只更新一次（15:00 后），交易时段不变
2. **数据源统一** — 所有非实时数据来自 MySQL 每日快照 or Redis 日终快照
3. **更新顺序固定** — 行情→信号→K线→归档，不可颠倒
4. **重入安全** — `data_rollover()` 可通过标志位检查是否已执行当日更新
